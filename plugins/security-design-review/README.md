# Security Design Review

Read a plan for how it will be misused, not for what it is called.

Reads a plan for security as a property of the layout rather than as equipment added later: who is meant to be where and how the building tells them, where somebody can be unobserved, where the boundary between public and controlled actually falls, and what happens to all of it after hours when the staff who make it work have gone home. Works the design questions first, because a camera is what gets bought when the plan did not answer them. Trigger on "security review", "CPTED", "is this plan secure", "where do we put the access control", "how do we secure this after hours", "security-design-review", or a plan for a building with a controlled boundary. Carries no standards, no ratings and no requirements; the client's security policy, the operator's rules and any regulation come from you. It does not design systems, does not do threat assessment, and does not replace the security consultant or the Architect of Record.

This is a skill. It runs in Chat, Cowork and Claude Code.
